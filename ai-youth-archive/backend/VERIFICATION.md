## 已覆盖

1. 注册、真实登录、错误密码、HttpOnly / SameSite Cookie；注册时自填 organizer 不会获得该角色，密码不以明文保存。
2. 未登录拒绝私有接口；缺少自定义请求头和错误 Origin 拒绝；不开放跨站预检。
3. 两个账号的作品、历史、附件、删除和导出互相隔离。
4. 公开申请在人工审核前不可见；审核后可见字段不含私人笔记、参赛自述、附件和用户名；重新编辑会重新待审；单条公开接口每次检查状态，返回 no-store。
5. 附件类型/文件名检查、私密下载、下载强制 attachment 和 nosniff；删除作品不误删资料库文件。
6. 动态待审核，关联私人作品时公开返回不暴露该作品 ID；同账号重复点赞不重复计数。
7. 正式退出会使原 Cookie 失效；服务重启后账号、会话和私人作品仍能读取。
8. 对同一账号从不同来源 IP 猜测密码仍受账号限流；异常 Origin、超长请求、非法 URL、非法关联 ID 被拒绝。

## 备份恢复实际流程

创建账号和私人作品 → 上传真实 UTF-8 附件 → 停止服务 → 运行 manage.py backup → SQLite integrity_check 返回 ok → 将数据库与 files 恢复到另一个空目录 → 从恢复目录启动服务 → 用原账号密码重新登录 → 读回原私人笔记 → 下载附件并逐字节比较相同 → 另一账号仍无法下载。

这证明当前备份/恢复方法在本地可用，不代表生产已启用自动备份。生产上线后仍需按实际服务账号、目录权限和计划任务检查一次。当前没有自动备份调度、自助找回密码、短信服务或比赛认证。
