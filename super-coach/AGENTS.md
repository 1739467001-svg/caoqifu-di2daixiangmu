# 探询项目记忆维护

项目所有者已明确要求：每次让助手记笔记时，要落入项目文件，并在后续模型请求中带入，不只停留在开发聊天里。

- 先读 `src/knowledge/project-notes.md` 和 `src/knowledge/owner-reminders.json`。
- 项目所有者在开发任务中明确提出的新提醒，保存到上述文件，记录日期和来源；更改行为时以最新明确确认版本为准，标明被替代的旧规则，避免矛盾同时生效。
- 原始设计附件在 `src/knowledge/design-notes-2026-09-26.md`。之后2026-09-26的最新纠正已替代固定题型、小结确认闭环及禁答规则：以解决问题、给可用答案为目标，穿插自由回答，小结留后台。当前行为在 `src/knowledge/coach-behavior-2026-09-26.md`；保留原附件作为历史背景。
- `src/project-memory.mjs` 和 `src/system-prompt.mjs` 构造每次请求的项目记忆；修改后检查注入测试。发布包与Docker镜像须包含 `src/knowledge`。
- 普通网站用户的提醒仅归属其当前任务，不更新全站规则；不同任务的笔记不得混用。删除和从历史继续时检查笔记快照。
- 笔记不保存API密钥、服务器密码、私钥或其他客户的私密对话。不把程序验证通过描述成真实用户的问题已解决。
- 7.0后最新节奏：短线知识、中线具体问题、长线项目、情绪陪伴中长线，按信息充分度推进。取消统一三轮上限与统一短答案；结果分段并标记重点，手机端保留完整内容与阅读位置。规则与事实覆盖记录随每轮请求保存，不能还原旧的强制收尾。
