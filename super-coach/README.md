# 探询 · AI 焦点教练

采用紧凑的左侧对话列表、右侧当前聊天窗口布局。左侧提供“新对话”、对话列表和“已归档”入口。未选中的对话仅带很淡的底色，没有描边或阴影，当前对话以荧光绿高亮，带黑色描边和硬阴影。每行右侧直接显示重命名、归档图标，悬停可看到操作名称，不必先切换对话。侧栏可以收起；手机上默认收进抽屉，通过聊天区左上角按钮展开，选择对话后自动关闭。没有文件夹、看板、资料表或问卷式交互。

视觉恢复到柔和化调整之前的奶油色网格、橙红 / 亮蓝 / 荧光绿配色、黑色描边和硬阴影，不再使用彩色渐变背景。品牌保留简洁的“探询”文字；聊天区保持开阔，没有包围对话的大外框。多任务功能与已保存对话保留。进入或刷新页面时播放约 2.5 秒的品牌入场动画，包含字标、装饰性加载条和向上揭幕；点击任意处或按 Escape 可立即跳过，系统设置“减少动态效果”时直接进入。动画不代表模型加载进度，也不等待 API，不影响连接失败时的重试。

交互带轻量过渡：侧栏在约 0.32 秒内滑动展开 / 收起，对话切换淡入，选中颜色与阴影渐变；新消息、列表条目和提示轻轻出现，移除条目时淡出，输入框随内容平滑增高。已有消息复用原节点，收到回复时只让新消息进入，不让整段历史重复闪动。连续操作可打断侧栏动画；系统设置“减少动态效果”时跳过这些动效。

提示文字沿用同一字体，仅重点内容加粗，使用半透明文字，不添加边框、底色或阴影。每条教练回复上方只显示处理耗时，不再重复品牌名称；耗时与正文之间用淡虚线分隔。快捷键、模拟状态和本地记录说明分组排列，手机上自然换行。正文保持原有对比度，时间与消息操作适当淡化，错误文字仍保持清楚可读。

输入框占位提示为“说说你的需求或想法…”，使用 42% 不透明度；辅助说明使用约 52%–55% 不透明度，不加粗边框。带粗线的用户气泡和输入按钮使用不透明配色。新对话页“理清问题”“找到自己的答案”使用绿色彩绘；教练回复最多强调三处短问题或开场重点，与选项及回答提示统一使用加深的绿色，加入轻微显现和光亮效果。彩绘仅使用安全文本节点，不解析模型输出中的 HTML，也不改变复制或发送的原文。


手机端输入区贴近底部安全区，辅助说明压成一行，隐藏桌面快捷键；普通打字不显示语音服务说明，也不保留它的空白占位。只有启用语音或键盘聚焦语音按钮时显示说明。新对话输入区也固定在可见区域底部，选项内容较多时在原面板内滚动。使用 VisualViewport 兼容仅缩小可见区域的手机键盘，保留页面缩放、16像素输入字号及44像素按钮。

## 直接运行

需要 Node.js 24 或以上，无第三方运行依赖。本地默认 Mock 无需 API Key；真实豆包对话需要服务器配置密钥。

在 `super-coach` 目录执行：

```powershell
node --env-file-if-exists=.env server.mjs
```

访问 http://127.0.0.1:3210 。Windows 也可双击 `start-preview.cmd`。没有 `.env` 时默认使用 Mock，出现“.env not found”不影响运行。可复制 `.env.example` 为 `.env` 隐去这条提示。

输入文字后按 Enter 发送，Shift + Enter 换行。中文输入法选字时不会误发送。网络失败会保留输入，可编辑后重发。

## 回复期间的输入、停止和排队

- 方块是彻底停止当前任务，不是暂停/继续。无论输入框有没有字，点方块都只取消当前请求，不顺便发送草稿。
- 停止后原提问、已收到的回答、草稿和未发送队列保留；停止的那段不再自动推进，没有恢复按钮。
- 在停止的任务里再输入并发送，仍在同一窗口开始新话题；历史保留可见，但不向模型传入旧消息或笔记。
- 想接着原话题聊，只能点提问或回答下的“从这里继续”，按所选位置建立分支；原任务保持不变。
- 回复期间仍可打字，明确点“排队发送”或按Enter排队一条。正常完成后自动发送；一旦停止，队列冻结并显示为未发送，不会偷偷继续。
- 记录自动存在当前浏览器。关闭、刷新中断的请求也保留为已停止；旧版暂停状态迁移为停止，不自动发起新的付费请求。未收到的模型内容不属于已保存记录。

## 消息操作

- 你的消息和教练回复下方都有复制、删除与“从这里继续”按钮，并显示发送时间；悬停时间可查看完整日期与秒数。
- 教练回复另显示服务器实际测得的处理耗时（不含浏览器到服务器的传输，真实模式包含服务器调用豆包的等待时间）。时间和耗时随消息保存在浏览器；更新前没有记录这些信息的旧消息显示“时间未记录 / 耗时未记录”。
- 点击消息下方的删除按钮直接弹窗确认，不进入多选、不框选消息。删除提问时，其对应回答会一起删除，弹窗会明确说明；单独删除回答则保留提问。只有“确认删除”才会删除，“取消”或 Escape 保留消息和草稿。切换对话会取消待确认删除，回复进行中不能删除。
- 删除会同步更新本地记录及后续模型上下文，其他对话和其余消息保留；本地保存失败时撤回本次删除并提示。删除全部消息后仍可直接输入继续。删除发送失败的提问时，同时移除其同文重试草稿；其他草稿保留。对话副本独立保存，删除不会影响“从这里继续”创建的其他对话。
- “从这里继续”会新建独立对话，保留原对话及其后续内容。点击教练消息时复制到该条回复为止；点击你的消息时复制其之前的上下文，并把该句话放回输入框，供修改或重新发送。不会自动发送，也不会把后来的内容带入新对话。
- 本地存储格式为版本 2，兼容原版本，保留已有任务。回答使用 replyToId 记录对应提问，旧记录按先前的提问补全关联。消息时间、ID、关联和处理耗时只在本地使用，发给模型的仍是角色和文字。

## 独立任务

- 点击左侧“新对话”进入居中的起始页，显示“你想让我帮你探询什么问题？”和输入框。此时不创建任务、不向模型请求开场白，也不增加侧栏条目。发送第一条非空消息后才创建独立对话；可直接询问客观问题或开始探讨，不强制先选模式；也可在输入框上方先选聊天方式再说话题。任务名称自动取这条消息的摘要，新的对话排在列表上方。
- 起始页的未发送内容单独作为草稿保存，切换到旧对话、重复点击“新对话”和刷新都不会产生空白任务或丢失草稿。旧对话的内容、草稿和正在等待的回复保持独立。第一次发送失败可在同一任务中重试，不重复创建。
- 手机侧栏支持点击遮罩或按 Escape 关闭，打开时键盘焦点保持在列表内，聊天输入区暂时不可操作。
- 点击每条对话的铅笔图标，在标题原位置修改名称，不弹窗。Enter、勾号或点击其他位置保存，Escape 或叉号取消；空名称保留原标题。自定义名称最多 60 个字符，保存后不被新消息覆盖。点击归档图标直接收起对话，不删除聊天内容；通过侧栏底部“已归档”查看，再点击恢复图标或“恢复对话”继续聊天。归档当前对话会切到其他普通对话；只剩最后一个普通对话时显示“这是最后一个对话，不能再归档。”，不归档，也不自动新建。
- 只有归档列表显示“彻底删除”垃圾桶图标。点击后先显示包含对话名称的确认框，提醒删除将失去全部消息和草稿且无法恢复；默认聚焦“取消”，支持 Escape 取消。只有明确点击“确认删除”后才移除该对话的聊天、草稿和本地记录，刷新后也不会返回；正在等待的回复不会让已删除的对话重新出现。删除正在查看的归档时切到另一条归档，没有其他归档时显示保留的普通对话。本地保存失败时保留原对话并提示删除未完成。
- 归档状态、自定义名称与聊天内容一起保存在当前浏览器。归档中的对话暂时不能发送新消息，已有请求仍可完成并保留回复；恢复后草稿、聊天与重试信息仍在。
- 每个任务单独保存聊天上下文、草稿、滚动位置、请求状态和重试信息。请求发出后可以切换或创建其他任务，返回的回复只属于原任务，不会串到当前对话。
- 任务与草稿写入当前浏览器的 localStorage，刷新后恢复。刷新中断的回复保留为已停止，接着聊请从消息下创建分支；直接输入会在同一窗口开始隔离的新话题，不自动重复发送。存储不可用时会在输入框下方提示，当前页面仍可继续使用。
- 没有账户或跨设备同步；清除本站浏览器数据会移除本地任务。服务器不保存客户任务；项目设计笔记则随服务端代码保存并在每轮加载。

## 当前真实教练规则

以2026-09-26项目所有者最新纠正为准，当前规则在 src/knowledge/coach-behavior-2026-09-26.md。原设计附件完整保留作为历史背景，冲突的禁答、固定题型和小结确认流程已被替代。每次调用都带入项目笔记、所有者提醒与当前任务事实笔记。

- 目标是帮助用户解决问题，拿到有依据的答案和具体下一步。信息够就直接答；还缺关键条件才温和追问1～2点。明确要答案时当轮给初步办法，不先拒绝或要求继续做题。
- 新对话直接输入即可，可主动展开“选项辅助 / 自由表达”偏好。偏好不锁定题型；刚用过选择题时下一轮为开放交流或答案，避免连续点选。选择题有2～4项，最后“其他，我自己说”只聚焦输入框。
- 服务端用严格JSON schema区分 kind=open/choice/answer。选择题问题在正文，选项在同页输入框上方；自由回答无需选题；答案直接显示，不出现小结确认弹框。历史小结保留为普通正文，不再折叠成“查看这次小结”。
- 取消统一三轮强制收尾。short知识短线直接回答；medium具体困难按关键条件推进；project长线按用户、痛点、场景、结果、范围、资源、验证标准逐步细问；support情绪陪伴走中长线，先倾听与承接感受，不诊断或承诺疗效。assessment保存事实覆盖、缺口、阶段和下一焦点，原文规则在知识文件中，不在界面显示评分或进度。明确要答案仍当轮给初稿，未确定的条件明确保留。
- 每个任务独立保存事实、诉求、待澄清点、矛盾、反复主题、已问角度、猜错的点及明确提醒。只存可核对信息，不存推理过程；小结在后台完成，不让用户反复确认。
- 笔记及快照随消息保存在本浏览器，有有效笔记时每轮带入最近至多20条、合计不超过30000字的消息；全部记录仍在本浏览器保存，支持恢复超过100轮的历史；无笔记时根据仍存在的历史重建。刷新保留，从历史继续只继承对应快照；删除会清除依赖旧历史的笔记；失败不推进状态。没有跨设备同步或服务器客户聊天数据库。
- 项目结果可400～1200字，情绪阶段答复可300～800字，按需要分段；模型highlights摘取原文重点，服务端和浏览器校验后以同色彩绘显示。复制保留原文，不执行HTML，刷新和分支保留标记。手机长回复从开头显示，读旧消息时保持位置；44px语音/发送与键盘可见区域适配保留。统一绿色彩绘、小圆角横条、无框自由表达提示与已有手机适配保留。模型文字只作为安全文本，不执行HTML。格式异常会明确失败，不展示原始JSON或伪造成功回复。
- 语义质量仍依赖模型。给出具体办法不代表一定有效，程序测试也不等于所有真实用户问题均已解决。

## 笔记如何持续带入

- `src/knowledge/project-notes.md` 记录已确认约定和规则优先级；`owner-reminders.json` 保存项目所有者的明确提醒；原始附件完整留存。它们每次构造模型请求都会带入，随发布包和镜像部署。
- 后续开发中用户说“记笔记”时，按项目 `AGENTS.md` 更新这些文件并验证部署。普通网站访客的“请记住”只保存到自己的当前任务，不改写全站规则。
- 当前任务的明确提醒保留原话，在下一轮系统上下文中带入；刷新恢复、任务隔离、分支快照、删除重建均受测试覆盖。删除含提醒的消息后不会从旧笔记再次带回。
- 这是文件与对话上下文记忆，不是训练模型本身，也不承诺跨设备或清除浏览器数据后恢复。

## 离线模拟对话

`USE_MOCK=true` 配合新版网页可离线演示可选偏好、选择题转自由回答、笔记保存及直接给出办法，提问文本只是固定演示，不验证理解能力。未带 coachProtocol 的旧接口保留此前的关键词演示：

- 从用户在起始页输入的问题开始，根据画画、编程、篮球等不同兴趣给出不同追问。原有对话的历史开场保留。
- 先回应具体内容或感受，再一次问一个开放问题。
- 接住“我饿了”“讲个笑话”等偏题；接受新的兴趣，不强制回原话题。
- 根据已有信息主动总结，或响应“帮我总结一下”；总结仍在聊天里，可以继续补充和纠正。
- 尊重“不知道”“不想说”“先不聊了”，不强制完成问题清单。

这是规则与关键词驱动的 Mock，不是大语言模型。它可演示上述场景，但不能像真实模型一样理解任意表达。不会按固定轮数或问题列表推进。

例如可以自然输入“我喜欢画画”，接着讲“昨天找不到画纸了”，再说“我想有个帮我整理画纸的工具”。也可以一次说明完整想法，或中途换个话题；这些不是必须按序执行的测试步骤。

## 模型替换位置

```
浏览器 dist/app.js
    → POST /api/chat { coachProtocol: 1, messages, interactionMode, coachState, action }
    → 服务端校验状态，注入项目笔记、最终规则、当前任务笔记和有效历史
    → src/ai.mjs 的 getAIReply()
    → { message: { role: 'assistant', content: '回复文字' }, coachState, interactionMode, mode, processingMs }
```

- `src/system-prompt.mjs`：组合项目持久笔记、最新行为规则和聊天偏好，发送给模型。
- `src/ai.mjs`：唯一模型接入函数 `getAIReply({ messages, systemPrompt, config })`。
- `src/mock-coach.mjs`：模拟回复策略，前端不含任何教练话术或问题逻辑。
- `src/config.mjs`：读取服务器环境变量，不返回密钥给浏览器。
- `dist/task-store.js`：独立任务状态、请求归属、草稿与本地保存；每次只把所属任务的消息发送到接口。
- `server.mjs`：HTTP 接口、输入校验、静态网页。没有新数据库依赖。

Mock 按代码中的规则近似执行教练策略，不会理解任意 System Prompt 修改。真实模式已接入豆包 Responses API，每轮把该 Prompt 作为 system 消息传给模型，并只携带当前任务的有效文字历史。

## 环境变量

复制 `.env.example` 为 `.env` 后按注释配置：

```dotenv
USE_MOCK=true
AI_PROVIDER=doubao
DOUBAO_API_KEY=
OPENAI_API_KEY=
AI_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
AI_MODEL=doubao-seed-2-0-lite-260428
```

`USE_MOCK=true` 不会访问外部模型，也不会产生 API 费用。填好 `DOUBAO_API_KEY` 后设为 `false`，重启即可使用豆包真实回复，调用会按供应商规则消耗额度。`OPENAI_API_KEY` 仍是保留配置，本次只接入豆包。

`getAIReply()` 使用[豆包官方 Responses 接口](https://docs.volcengine.com/docs/ark/create-model-responses-api?lang=zh)。请求超时 55 秒，旧文字接口最多输出1536 tokens，新教练协议最多5000 tokens（含结构化笔记），使用JSON输出格式，关闭深度思考；只取最终回答文本，不展示内部分析或工具内容。模型错误、凭据失效、繁忙和超时会转换为中文提示，不自动重试付费请求、不降级成假回复。

Key 只填本地或服务器环境，`.env` 已被 Git 和 Docker 构建排除。生产环境由 Compose 读取 `/opt/tanxun/runtime.env`（root 所有、权限 600），放在发布目录外，不进入镜像或上传包。更新密钥后重新创建探询容器使其生效，不把该文件内容或 `docker compose config` 的完整展开结果贴到聊天中。

前端接收回复、模式与当前任务的事实笔记，不读取 Key、供应商配置或 System Prompt。真实模式会把当前任务的有效历史发送至豆包生成回复，浏览器仍保存自己的记录。请求使用 `store:false`，不创建可供后续查询的 Responses 对象，不使用 `previous_response_id`；删除、修改或分支后的下一轮只发送现存消息。此设置不代表供应商不保留运营或安全日志，也无法撤回已经处理过的内容。

## 当前范围

这一版支持浏览器本地的多任务对话，服务端不写入数据库或档案文件。对话事实笔记随当前浏览器的任务保存，不是跨设备长期记忆；不生成独立的孩子画像或档案。

旧版本的 `data/` 数据没有被删除或迁移，新版本也不会读取或公开它。旧问卷接口已下线，星空展示暂不出现在这版界面。浏览器语音输入见下文。

正式网址为 https://112.74.63.237/。部署配置、验证结果和更新步骤见 [DEPLOYMENT.md](DEPLOYMENT.md)。内部端口为 3210，健康检查 `/api/health`，返回运行模式；健康检查不额外调用付费模型。浏览器的任务和消息 ID 兼容旧 HTTP 公网 IP 访问。

## 语音输入

麦克风与发送按钮始终可见，空闲时用淡色呈现，失去输入框焦点也能点击。手机和桌面端统一为 44 × 44 像素，录音时保持麦克风图标，只改变颜色。输入框在手机端保持 16 像素字号，避免输入聚焦导致自动放大。

语音使用浏览器的 SpeechRecognition / webkitSpeechRecognition，语言为 zh-CN，无需教练模型 API Key。浏览器可能向其在线语音服务传输音频；本项目服务器不接收或保存音频。转写结果仅进入当前草稿，用户确认后再发送。点击停止、按 Escape、切换任务或离开页面会停止收音，单次最多 60 秒。

公网需要受信任的 HTTPS；localhost 可用于开发。不支持的浏览器、拒绝权限、没有麦克风或识别网络不可达时，会提供明确提示，文字输入仍可用。没有 SpeechRecognition 的浏览器会在点击后聚焦原输入框、保留草稿，提示使用输入法键盘上的麦克风；在微信中也可从菜单选择在浏览器中打开。根据实际能力检测，不因浏览器名称屏蔽已有支持。现阶段没有独立云端 ASR 或微信 JS-SDK，不能保证所有浏览器/网络均支持网页直接识别。核心会话状态和迟到结果隔离测试位于 tests/voice-input.test.mjs。
