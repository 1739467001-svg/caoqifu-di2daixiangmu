# 探询 · 项目长期笔记

更新：2026-09-26。此文件用于每次模型调用时恢复项目约定；它不是模型训练数据，也不是客户之间共享的聊天记录。

## 当前已确认

- 2026-10-10所有者要求删除服务器上的探询网站，已执行并验证原HTTP/HTTPS网址返回410。应用容器、镜像、发布文件和服务器运行密钥已删除；另一网站共用的证书工具保留。本地代码仍保留，未经新的明确请求不再部署。此决定取代此前网站持续上线的状态。

- 2026-09-26状态呈现补充：等待回复时使用“我在认真听，也在想怎样陪你继续聊…”等温和提示。停止后原位置显示暂停图标和“当前对话已被暂停”，发送键在空草稿时显示双竖线暂停形状；输入新文字恢复发送箭头。此处暂停仅为界面用词，仍停止请求，不恢复生成，不改变同窗口新话题隔离规则。

- 名称是“探询”，询问的“询”；通用思考教练，面向不同用户，不限定俱乐部孩子。
- 2026-09-26产品版本定为7.0：左上角品牌旁用小字显示v7.0。按钮、说明、标题、状态和辅助提示统一为常规细字重400；品牌字标保留原设计，教练正文的重点彩绘强调仍可加粗，不把界面提示混用多种粗细。
- 对话在一个页面进行，文字收发，语音先转文字、由用户确认后发送。
- 温和、共情、口语化；问题要简单具体，不能以温柔为由堆长句，不像考官，不附和观点。
- 2026-09-26最新明确纠正：以帮助用户解决问题、得到可用答案为目标。选择题只在有帮助时使用，穿插自由回答；信息够时直接给出有依据的判断和具体办法。用户要答案就当轮给，不先拒绝或要求多答一轮。
- 小结留在后台，不再展示“查看这次总结/小结”或强制确认按钮，不把全部问题抄一遍作为结果。旧附件中的固定题型、小结确认闭环和禁止建议规则已被替代。当前完整行为规则在 coach-behavior-2026-09-26.md。
- 模式只是偏好且可不选；换方式保留笔记。“不知道”换个具体角度、必要时给选项。明确停止时停止。
- 2026-09-26最新节奏：short知识短线直接答；medium具体困难问清关键条件；project项目长线细问用户、痛点、场景、目标、首版范围、资源限制与验证标准；support情绪陪伴走中长线，先关心和倾听，按对方需要交流。取消统一三轮强制作答和100～250字限制，信息充分度而非轮数决定阶段。项目/陪伴的详细结果分段并以同色彩绘标重点，适配手机长文阅读，不加分类进度面板。
- 后台笔记记录用户事实、模糊点、矛盾、反复主题和已问角度，每次请求都带入；不要把推测写成事实，不保存推理过程。
- 每个任务的对话、草稿、模式和笔记独立。删除后不从旧笔记带回被删信息；从历史继续只使用当时的记录。
- 2026-09-26发送控制最新纠正：方块点击后停止当前请求，已收到的文字和历史记录保留。停止后直接发送仍在同一对话窗口和侧栏条目里开始新话题，不把停止前的消息及用户笔记发给模型；旧排队消息保留为未发送记录，不自动发送。只有从某条消息“从这里继续”才使用那一段的历史及笔记。刷新、删除消息不能破坏上下文隔离。此规则替代“停止后新建独立任务”，不提供暂停恢复。
- 前端保留奶油色网格、醒目绿彩绘、蓝色用户气泡和紧凑侧栏。选项为小圆角横条，在输入框上方展开，不新建独立弹窗页面。多问题不让用户挑题。
- 2026-09-26手机适配要求：底部输入框尽量靠下，辅助提示紧贴输入框；手机不展示桌面快捷键说明，不让隐藏语音说明占位，给主对话留更多空间。保留44像素语音与发送按钮、16像素输入字号及安全区，键盘弹起时跟随可见区域。
- 模型密钥只放服务器环境变量；本项目资料不包含密钥、密码或其他客户私密对话。
- 当前没有账号系统、跨设备同步或服务器聊天数据库。记录随此浏览器保存；不能向用户承诺跨会话全局记忆。

## 本次明确要求记住的提醒

用户原话：“把聊过的所有笔记喂给模型。由于 API 接口的原因，每次沟通都像面对一张白纸，所以要把这些笔记作为网站的记录和底层代码。每次我让你记笔记时，都要把我的提醒记入笔记中；下次调用模型时，要用这些笔记让模型回忆起来。”

执行：维护本文件、owner-reminders.json 和附带设计原稿，每次构造服务端系统提示词时加载。普通客户提出“记住/记笔记/提醒”时仅保存到其自己的任务提醒，不能改写所有用户共享的项目规则。后续网站修改任务收到项目所有者的新提醒时，更新此目录与版本记录，验证后部署；不只停留在当前聊天。
